## Unified AI Exercise Pipeline

Space Analysis recommendations and AI-generated exercises are the same thing — exercises generated by AI from different triggers. They share one pipeline:

```
AI generates exercise (triggered by Space Analysis OR exercise library gap)
        ↓
Store in exercises table
  source_type: 'generated_template'
  review_status: 'pending'
  is_active: true  ← immediately usable (Phase 1 decision)
  generated_for_user_id: <uuid>  ← trail for quality control
        ↓
Admin reviews in Supabase table editor (filter review_status = pending)
        ↓
Approve: review_status = 'approved', review_status = 'reviewed_generated'
Reject:  is_active = false
        ↓
Approved exercises enter shared pool — available to all users whose preferences match
```

**Why:** One pipeline, two entry points. No duplicated logic. Space Analysis becomes a discovery mechanism, not an isolated feature.

## Phase 1 vs Phase 2

**Phase 1 (current — ship now):**
- AI-generated exercises auto-approved: `is_active: true`, `review_status: 'approved'`
- Immediately usable by the generating user
- **Note:** Changed from `'pending'` to `'approved'` on 2026-04-23 — Dashboard filters for `'approved'` so pending exercises were invisible to users
- `generated_for_user_id` stored for audit trail
- Safety net: AI prompt is schema-constrained + existing `validateExerciseCandidate` filters

**Phase 2 (deferred — build when volume demands it):**
- Admin review UI as a built screen in the app
- Trigger: ~50+ generated exercises in the DB OR first quality complaint
- Until then: Supabase Dashboard → Table Editor → filter `review_status = pending` → edit rows directly
- No code needed for Phase 2 until problem is real

**Why deferred:** Zero AI-generated exercises exist yet. Build tooling for actual problems, not hypothetical ones.

## Admin Review via Supabase Table Editor (interim workflow)

The `exercises` table schema already supports review:
- `review_status: 'pending' | 'approved' | 'rejected'`
- `is_active: true | false`
- `source_type: 'curated_seed' | 'generated_template' | 'reviewed_generated'`

Admin workflow (no code required):
1. Supabase Dashboard → Table Editor → exercises
2. Filter `review_status = pending`
3. Review row, edit directly: flip `review_status` → `approved` and `is_active` → `true` to promote, or `is_active` → `false` to reject

## Multi-Provider AI Architecture

All AI calls go through `supabase/functions/_shared/ai/`:
- `types.ts` — capability interfaces and I/O types
- `provider.ts` — factory routing capabilities to models via env vars
- `models/claude.ts` — Claude implementation (direct fetch, no SDK)
- `models/openai.ts` — OpenAI stub (ready to implement)

Config pattern (secrets only, no code changes to swap models):
```
AI_SPACE_ANALYSIS_PROVIDER=claude
AI_SPACE_ANALYSIS_MODEL=claude-sonnet-4-6
ANTHROPIC_API_KEY=sk-ant-...

# Future capabilities follow same pattern:
AI_EXERCISE_GEN_PROVIDER=claude
AI_EXERCISE_GEN_MODEL=claude-haiku-4-5-20251001
AI_NUDGE_COPY_PROVIDER=openai
AI_NUDGE_COPY_MODEL=gpt-4o-mini
```

Each capability is independently routable to the model best suited for that task.

## Space Analysis → Exercise Flow

Space Analysis does NOT return free-form recommendation blobs. It returns structured `Exercise` objects matching the `exercises` table schema. These are stored in the DB and immediately launchable via ExerciseDetail.

The `analyze-space` edge function:
1. Calls AI with a prompt that outputs structured exercise schema
2. Stores generated exercises in `exercises` table
3. Returns full Exercise objects to the client
4. Client can launch them directly into ExerciseDetail
